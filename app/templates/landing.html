Two models scored identically — but behaved completely differently

In our experiments, Llama 3.1 8B and Llama 3.2 3B both scored 100% pass rate on an 8-case coding assistant test suite. A traditional single-score evaluation would declare them identical. BehaviorCI's dual-signal approach revealed something different: the embedding distance between their safety refusal outputs was 0.73 — indicating fundamentally different refusal behaviors completely invisible to score-based evaluation alone.

How it works

BehaviorCI treats AI behavior the same way software engineers treat code — with automated tests, version-controlled expectations, and CI/CD gating.

1

Define test cases in YAML

Write prompts, expected behaviors, and evaluation criteria in version-controlled YAML files — just like unit tests for code. Load them with python cli.py sync my_suite.yaml.

2

Run against your model

BehaviorCI calls your model endpoint for each test case, then judges the output across 4 independent dimensions: correctness, hallucination, format, and behavioral tone.

3

Dual-signal evaluation

The LLM judge scores quality. Embedding distance independently measures semantic drift. Both signals together catch regressions that either signal alone would miss.

4

Regression diff engine

Run N is automatically compared against Run N-1. Metric drops, pass→fail flips, behavioral drift, and systemic patterns are all detected and reported.

5

CI/CD gates your deployment

The CLI exits with a non-zero code on regression — failing your GitHub Actions build automatically. The regression report is posted as a PR comment for the reviewer to see.

The dashboard shows a git-diff-style report comparing this run against the last one.

Everything included

One framework, every tool you need to keep your AI product's behavior under control.

⚖️

4-Dimensional LLM Judge

Scores correctness, hallucination, format, and behavioral tone independently. A single aggregate score loses the signal of which dimension regressed — BehaviorCI never aggregates.

📐

Embedding-Based Drift Detection

Cosine distance between run N and N-1 outputs catches behavioral drift even when scores look fine. The dual-signal approach detects what judge scores alone miss.

🔀

GitHub Actions Integration

Fails your CI build automatically when regressions are detected. Posts the full regression report as a PR comment. No extra tooling needed — works with any GitHub repo.

📊

Trend Dashboard

Pass-rate and per-dimension score history across all runs. Login-protected, per-organization. See the moment behavior changed and trace it to the right deployment.

🏢

Multi-Tenant Architecture

Every organization gets an API key. Complete data isolation enforced at both the API and dashboard level — one org can never see another's data.

🔔

Slack & Email Alerts

Get notified the moment a regression is detected. Configurable Slack webhook and SMTP email — both optional, both free to set up.

💰

100% Free to Run

Uses Ollama for the LLM judge (local, open models), sentence-transformers for embeddings (local CPU), and PostgreSQL for storage. No API keys, no cloud bills.

🔌

Model-Agnostic

BehaviorCI tests what your model produces — it never assumes which model you're using. Works with OpenAI, Anthropic, Ollama, or your own fine-tuned model behind an API.
